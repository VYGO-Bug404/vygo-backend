4.1 Consulta de entrada completa
Esto es literalmente lo que el agente ejecuta para construir su estado.

-- 1) Estado del repartidor y su viaje activo
select r.id, r.vehiculo, r.disponible,
coalesce(uc.lat, st_y(v.origen_actual::geometry)) as lat,
coalesce(uc.lng, st_x(v.origen_actual::geometry)) as lng,
v.id as viaje_id, v.iniciado_en, uc.updated_at
from repartidores r
left join viajes_repartidor v
on v.repartidor_id = r.id and v.estado = 'activo'
left join ubicaciones_conductores uc on uc.user_id = r.usuario_id
where r.id = :repartidor_id;
-- 2) Plan activo: qué lleva a bordo y en qué orden
select vp.orden, p.id, p.precio, p.estado,
st_y(p.origen::geometry) as origen_lat,
st_x(p.origen::geometry) as origen_lng,
st_y(p.destino::geometry) as destino_lat,
st_x(p.destino::geometry) as destino_lng,
p.contexto, p.creado_en, p.aceptado_en, vp.agregado_en
from viaje_pedidos vp
join pedidos p on p.id = vp.pedido_id
where vp.viaje_id = :viaje_id
and p.estado in ('asignado', 'en_camino')
order by vp.orden;
-- 3) Ofertas pendientes que hay que decidir ahora
select o.id, o.pedido_id, o.ronda, o.radio_metros,
o.desvio_estimado_metros, o.expira_en, o.clima,
p.precio, p.app_id, p.contexto,
p.origen_direccion, p.destino_direccion,
st_y(p.origen::geometry) as origen_lat,
st_x(p.origen::geometry) as origen_lng,
st_y(p.destino::geometry) as destino_lat,
st_x(p.destino::geometry) as destino_lng,
a.nombre as app
from ofertas_pedido o
join pedidos p on p.id = o.pedido_id
join apps a on a.id = p.app_id
where o.repartidor_id = :repartidor_id
and o.estado = 'pendiente'
and o.expira_en > now()
and a.nombre in (select platform from platform_connections
where user_id = :user_id and is_active)
order by o.ronda asc, o.desvio_estimado_metros asc
limit 8;
-- 4) Ganancia y horas del turno, para rho_actual
select coalesce(sum(p.precio), 0) as ingreso_mxn,
count(*) as entregados,
extract(epoch from now() - min(v.iniciado_en))/3600.0 as horas
from viaje_pedidos vp
join pedidos p on p.id = vp.pedido_id
join viajes_repartidor v on v.id = vp.viaje_id
where v.repartidor_id = :repartidor_id
and p.estado = 'entregado'
and v.iniciado_en >= date_trunc('day', now());

Límite de 8 ofertas. No es arbitrario: el vector de observación del modelo tiene exactamente 8 ranuras de oferta. Si
llegan más, se toman las 8 mejores por anillo y desvío. El HÍBRIDO tolera cualquier número, pero se mantiene el
mismo límite para que las dos políticas vean lo mismo y la comparación sea legítima.

5.3 Escritura de vuelta a la base
La decisión no sólo se devuelve al frontend: se persiste. Este es el segundo tipo de salida y es el que deja rastro auditable.
-- Al ACEPTAR una oferta
update ofertas_pedido
set estado = 'aceptada', respondida_en = now(), viaje_id = :viaje_id
where id = :oferta_id;
update pedidos
set estado = 'asignado', aceptado_en = now()
where id = :pedido_id;
-- Las demás ofertas del mismo pedido pierden (anillo más externo o más lejos)
update ofertas_pedido
set estado = 'perdida'
where pedido_id = :pedido_id and id <> :oferta_id and estado = 'pendiente';
-- El plan reoptimizado se escribe COMPLETO: todos los orden cambian
insert into viaje_pedidos (viaje_id, pedido_id, orden)
values (:viaje_id, :pedido_id, :orden_nuevo);
update viaje_pedidos set orden = :nuevo_orden
where viaje_id = :viaje_id and pedido_id = :pedido_id;

-- por cada parada

update viajes_repartidor
set ruta_linea = st_setsrid(st_makeline(/* puntos en orden */), 4326),
actualizado_en = now()
where id = :viaje_id;
-- Al RECHAZAR
update ofertas_pedido
set estado = 'rechazada', respondida_en = now()
where id = :oferta_id;

El orden de viaje_pedidos se reescribe entero, no se agrega al final. Aceptar un pedido nuevo puede cambiar el
orden de todos los demás — ése es el punto del secuenciador. Si sólo insertas la fila nueva con orden = max + 1 , el
mapa mostrará una ruta que el agente nunca recomendó, y la ganancia real no coincidirá con la proyectada.

6.1 Distribución geográfica — lo que decide si hay agrupamiento
No muestrees los orígenes uniformemente sobre la ciudad. Si los comercios están dispersos, no hay dos
recolecciones cerca y el agrupamiento es imposible por geometría, sin importar qué tan bueno sea el agente. Usa 4
clústeres de ~10 comercios cada uno en un radio de 1.5 km, y muestrea los destinos dentro de 2.5 km del origen.
